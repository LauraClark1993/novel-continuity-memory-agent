# 状态与上下文约束

## 数据隔离

每一本小说、每个实验组必须使用独立SQLite数据库和独立输出目录。初始化前检查正文、大纲、状态中的章节编号都属于当前小说。禁止将检索组、整书上下文组或其他小说的状态混入当前运行。

## 最小充分上下文

每章只选择：最近章节正文和上一章结尾、相关人物状态与知识边界、相关地点及空间关系、当前矛盾、相关伏笔、三章滚动剧情窗，以及任务卡的必做和禁止事项。

不要因为“可能有用”而发送全部历史正文。检索不足时，补充命中的事实或扩大有限窗口，不直接退化成整书上下文。

## 更新事务

只有确认正文能够更新正式状态。更新至少覆盖本章事实、人物与地点变化、知识边界、矛盾、伏笔、时间推进和章节结尾。解析或写入失败时保留已确认正文与进度，下一次先恢复状态更新，不重复生成正文。
