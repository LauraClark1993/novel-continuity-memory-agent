# 长篇小说一致性记忆

把本 Skill 作为基础 NovelMemory Agent 的编排层：Skill 决定读取和更新什么上下文，基础 Agent 负责模型调用、正文生成与机器审核。不要复制基础 Agent，也不要把 API Key、小说数据库或实验正文打包进 Skill。

## 工作流

1. 运行 `scripts/novel_skill.py doctor`，确认项目、数据库、小说与 API 配置彼此匹配。不得跨小说或跨实验组复用数据库。
2. 新小说先导入前置正文和完整大纲，再初始化结构化故事状态。已有有效状态时不要重复初始化。
3. 生成当前章节时，只组装任务卡、近期正文、相关事实、人物与地点状态、未解决矛盾、伏笔、章节结尾状态和三章滚动剧情窗。不要发送截至当前的全部正文。
4. 正文通过机器审核后再确认，并以确认正文更新故事状态；失败草稿不得污染正式状态。
5. 批量运行必须设置起止章节、目标字数、最大重写次数和预算停止线。中断后从进度文件记录的下一章续跑。
6. 完成后先用 `evaluate` 导出 Token、缓存、估算费用和上下文统计，再用 `evaluate-quality` 调用与生成流程隔离的独立裁判，输出逐章八维评分、双向证据、严重度和生产审核漏检率。财务结论以模型供应商后台实扣为准。

## 固定约束

- 每章第一行必须是“第X章 章节名”。
- 默认目标约 3000 字；自然展开即可，正文不超过 6000 个非空白字符。不要为了贴近目标字数额外调用模型压缩。
- 任务卡锁定后，重写只能修复缺失项和冲突，不得改变章节目标或提前发生后续剧情。
- 地点必须使用状态库中的正式名称，避免笼统或互相混淆的院落名称。
- 网络错误、输出截断和 JSON 解析错误应保留断点；重试次数必须有上限。
- 当前版本不包含人工审核工作台。用户可以审阅产物，但Skill不自动改写用户正文。
- 生产审核只控制草稿能否进入后续上下文；独立实验评测不得触发重写。正式问题必须同时包含候选正文证据和任务卡、历史上下文或原作参考依据。
- 本地金额统一称“估算费用”；后台账单才是最终实际费用。
